# Safe Slate development and testing

- `npm run editor` is the developer's normal Tauri editor. It uses the normal sidecar and existing data. Do not launch it for automated smoke tests.
- Backend changes require rebuilding the normal sidecar with `npm --prefix editor run build:server` before normal development. Do this only as an intentional normal-development build, with Slate closed; never as part of QA verification. Editor and sidecar lifecycle versions must match.
- Use `npm run editor:qa` for manual QA. It creates a fresh `.qa/sessions/<UUID>/data`, builds its own sidecar, and uses `.qa/target` for Cargo/Tauri outputs. The QA window is titled **Slate Editor QA**. `-- --build-only` builds without launching; `-- --prepare-only` only creates session configuration.
- QA requires installed client/editor npm dependencies and `server/.venv` with `requirements.txt` and PyInstaller. See the README for setup.
- Python development defaults to `server/data`; frozen development/installed sidecars default to the platform's Slate user data directory. `SLATE_DATA_DIR` explicitly overrides both the database and authentication token location. Never point QA at personal data, copy personal databases/tokens into fixtures, or delete/migrate/reset personal databases for a test.
- `SLATE_ENV=qa` requires a UUID session, an absolute `<UUID>/data` directory with its matching `.slate-qa-session` marker, and Tauri lifecycle identity. Use the launcher to supply these. Never bypass validation to get a test running.
- Never copy QA executables into `editor/src-tauri/target`, `editor/src-tauri/binaries`, or normal `server/build`/`server/dist`. Do not rebuild shared development executables during QA verification. Use `npm run editor:qa -- --build-only` for build checks.
- If ports 8000 or 1420 are occupied, report it or let the developer close their app. Do not kill processes by name/port or trust a health endpoint PID. Only the owning editor may shut down its own sidecar.
- QA uses localhost only. **Quit** in the tray ends a session; closing the window retains the existing hide-to-tray behavior. Each subsequent QA launch starts with fresh data. Keep `.qa` sessions for inspection; remove only known QA session artifacts after their processes have exited.
- Run `server/.venv/Scripts/python.exe -m pytest server/__tests__`, `npm run test:qa`, and the relevant client/editor tests. Use temporary fixtures and isolated build outputs. Importing the server factory does not open a default database; external ASGI runners use `uvicorn main:build_app --factory` from `server`.
